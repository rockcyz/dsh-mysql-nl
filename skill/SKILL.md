# MySQL 自然语言查询

## 这个技能解决什么问题

模型不知道用户库里有哪些表、字段叫什么、外键怎么连。直接写 SQL 通常会**编造字段名**（写 `SELECT title FROM movies`，真实表却是 `film`）或漏掉 JOIN 条件。

这个技能提供两件事，其余都交给调用方：

1. **真实结构接地** —— `schema` 从 `INFORMATION_SCHEMA` 读出表、字段、类型、主键、索引、外键。
2. **安全执行** —— `query` 在只读校验、行数上限、语句超时、结果截断之后才执行。

**选表和写 SQL 是调用方（你）的工作** —— 你本身就是模型，不需要额外的模型调用。

## 找到 CLI

先确定可执行文件位置，后面每一步都用它：

```bash
# bash / git-bash
MYSQL_NL=$(ls .agents/skills/mysql-nl/bin/mysql-nl.mjs \
              ~/.agents/skills/mysql-nl/bin/mysql-nl.mjs 2>/dev/null | head -1)
```

```powershell
# PowerShell
$MYSQL_NL = @("$PWD/.agents/skills/mysql-nl/bin/mysql-nl.mjs",
              "$HOME/.agents/skills/mysql-nl/bin/mysql-nl.mjs") |
            Where-Object { Test-Path $_ } | Select-Object -First 1
```

两条都找不到时，问用户技能装在哪，或让用户设置环境变量 `MYSQL_NL` 指向 `bin/mysql-nl.mjs`。所有命令都是 `node "$MYSQL_NL" <子命令>`。

## 工作流（照做，别跳步）

### 第 1 步：确认连接可用

```bash
node "$MYSQL_NL" list      # 列出配置好的连接，不显示密码
node "$MYSQL_NL" ping      # 连通性 + 服务器版本
```

`list` 报「找不到连接文件」时，**不要自己猜连接参数**。让用户在工作目录建 `mysql-nl.json`：

```json
{
  "version": 1,
  "default": "local",
  "connections": [
    {
      "id": "local",
      "label": "本机 MySQL",
      "host": "127.0.0.1",
      "port": 3306,
      "user": "root",
      "password": "${env:MYSQL_PWD}",
      "database": "world",
      "readOnly": true,
      "maxRows": 200,
      "maxQueryMs": 15000
    }
  ]
}
```

要点：`password` 可以写 `${env:变量名}` 避免明文；`readOnly` 默认就是 `true`；键名写错会被**拒绝并提示**，不会被静默忽略。

### 第 2 步：先读真实结构 —— 这一步不能省

```bash
node "$MYSQL_NL" schema --db world                      # 整库结构
node "$MYSQL_NL" schema --db world --tables film,actor  # 只要这几张表
node "$MYSQL_NL" schema --db world --brief              # 表多时先看表名清单
```

表超过约 30 张时：先 `--brief` 拿表名和行数，挑出相关表，再用 `--tables` 取其完整字段。**不要**把整库结构一次读进上下文。

### 第 3 步：有歧义先问，不要猜 —— 写 SQL 之前

先判断：**用户给的条件能不能唯一确定他要的东西？** 不能就停下来问，别硬写。

三种要停下来问的情况：

| 情况 | 例子 | 做法 |
|---|---|---|
| 条件值**命中多行** | 「查葛波的成绩」，而库里有 2 个葛波 | 列出候选，带上区分信息，让用户选 |
| 条件值**命中 0 行** | 用户说的名字库里没有（可能记错/错别字） | 别直接说"没有"，用 `LIKE '%…%'` 查近似值，把最接近的候选给用户确认 |
| 条件**缺省** | 「查一下成绩」——没说谁的、也没说哪门课 | 问清范围再查 |

提问要给**编号和区分信息**，不能只说"有两个人"：

```
「葛波」在库里有 2 位，你查哪一位？
1. 2000014 葛波（计算机系）
2. 2000020 葛波（会计系）
```

确认后，用**唯一键**（主键/学号等）重写条件再执行。硬规则：

- 用户回答之前**不要执行**，也不要把多个候选混在一份结果里
- 用户明确说「都查」时才返回多条，并且**每行都要带唯一键**，否则他分不清
- 已经由主键唯一限定的查询**不要多问** —— 别为了走流程而打断用户
- 一次问清所有歧义，不要来回追问三轮

### 第 4 步：你自己写 SQL

只用 `schema` 输出里**真实出现过**的表名和字段名。拿不准就重新 `schema` 看，绝不靠记忆猜。

### 第 5 步：执行

```bash
node "$MYSQL_NL" query --sql "SELECT c.Name, COUNT(*) AS city_count
FROM city c JOIN country k ON c.CountryCode = k.Code
GROUP BY c.Name ORDER BY city_count DESC LIMIT 10"
```

常用参数：`--db <库>`、`--max-rows N`、`--json`（机器可读）。SQL 里有 `--` 开头的注释时用 `--sql -` 从标准输入传。

### 第 6 步：报错了就改，不要重试同一句

MySQL 返回的错误信息（`Unknown column 'x' in 'field list'` 等）会原样打印到 stderr。**读它**，必要时重新 `schema` 确认字段，改完再跑一次。禁止把同一条报错的 SQL 反复重试。

## 硬规则

- **歧义不要靠猜**。条件值可能对应多个对象时，先列候选让用户确认，再用唯一键重写条件。猜错不会报错，只会安静地给出一份错答案 —— 这比报错危险得多。
- **绝不编造**表名、字段名、外键关系。只用 `schema` 输出里出现过的标识符。
- **不要绕过只读**。被拒绝时退出码是 `2`，stderr 说明原因。这是策略答复，不是故障——不要改写语句去规避它。
- **写操作**：连接配置里显式写了 `"readOnly": false` 才可能执行写语句；CLI 没有绕过开关。用户要求改数据时，先确认这是他们真要的。
- **结果不是全部**：输出里出现「已按上限 N 行截断」时，要告诉用户结果被截断了，不要当成完整数据下结论。
- **别把行数当准确值**：`schema` 里的行数是 `INFORMATION_SCHEMA` 的估算值，不是 `COUNT(*)`。

## 输出格式（硬性要求，不是建议）

这是给计算机专业学生用的教学工具。**只报数字是不合格的回答。** 每次执行查询后，必须按下面
四段顺序输出，一段都不能省：

````
### 1. 执行步骤
   （`query` 命令的 stdout 已经给出，原样保留即可）

### 2. SQL 语句
   ```sql
   （原样保留命令输出的 SQL）
   ```

### 3. 语句讲解
   （命令已给出逐子句结构说明 + 教学提示，保留它们，
     并在后面用一两句话补充**语义**：这条 SQL 为什么能回答学生的问题）

### 4. 查询结果
   （命令给出的 markdown 表格，原样保留）
````

补充要求：

- **不要**把 `query` 的 stdout 压缩成一句"查询到 5 行"。那四段就是交付物本身。
- 第 3 段要**在命令给出的结构讲解之外**补上语义解释，因为命令只能解释"每个子句在做什么"，
  不知道学生想问什么。例如："因为要按国家统计城市数量，所以用 `City` 与 `Country` 做 JOIN，
  再按 `Country.Name` 分组计数。"
- 涉及新语法时，点出**关键概念**：`WHERE` 与 `HAVING` 的顺序、`JOIN` 与笛卡尔积的区别、
  聚合函数为什么不能写在 `WHERE` 里。这是学生真正要学的东西。
- 命令输出里的「**教学提示**」如果出现，**必须**转述给学生 —— 那里是 `SELECT *`、
  缺 `ON` 条件、`WHERE` 里用聚合函数这类最典型的错误。
- 执行失败时（退出码 1），命令仍会输出步骤、SQL 和讲解。**把它们照样展示**，
  再说明数据库报了什么错 —— 报错的语句是最有教学价值的例子。
- 有意的错误示范（例如漏掉 JOIN 条件导致笛卡尔积）比只给正确答案更有价值，
  但必须明确说清"这是错的，错在哪"。

## 子命令速查

| 命令 | 作用 |
|---|---|
| `list` | 列出所有连接（不含密码）和连接文件路径 |
| `dbs` | 列出服务器上的数据库 |
| `ping` | 连通性 + 服务器版本 |
| `schema --db X [--tables a,b] [--brief] [--max-chars N]` | 紧凑的表结构文本 |
| `query --sql "..." [--db X] [--max-rows N] [--json]` | 只读执行并输出表格/JSON |

通用选项：`-c/--connection <id>`、`-f/--file <路径>`、`--cwd <目录>`、`-h/--help`。

## 退出码

| 码 | 含义 | 该怎么做 |
|---|---|---|
| 0 | 成功 | 读 stdout |
| 1 | 配置/SQL/运行时错误 | 读 stderr，修配置或改 SQL |
| 2 | 被只读策略拒绝 | 如实告诉用户，不要绕过 |
| 64 | 用法错误 | 看 `--help`，修参数 |

## 没有 MySQL 时

用户还没装 MySQL（或想先练习）时，`world` 和 `sakila` 是官方示例库，装完直接可用。告诉用户需要先起一个 MySQL 实例并建好连接文件，不要假装查到了数据。
